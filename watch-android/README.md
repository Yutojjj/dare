# 付け回しウォッチ APK 2.0（Wear OSネイティブ版）

Galaxy Watch4で利用できないWebViewを廃止し、Android Canvasで円形画面を直接描画します。ブラウザのインストールは不要です。既存PWAアイコン、ダーク背景、白文字、現在卓の黄色、30秒未満の赤・1分未満のオレンジに合わせています。

## 含まれる機能

- 一覧の検索、端末別の小中大、タイマー順・卓数順・名前順、並び替えアニメーション
- 一覧から再生・一時停止・次の卓、長押しで推移編集・削除
- 操作画面のリセット・再生・一時停止・±10秒/±1分、時間候補と自由設定ダイヤル
- ダイヤルは分単位・秒は10秒刻み。選択した時間は再生するまで停止
- 押した順の推移卓設定、1卓のみの登録、メインアプリのキャスト候補と「本日」切替
- 卓ごとの設定時間を保存し、移動先の保存時間で停止状態にリセット
- 卓移動・時間設定の履歴、確認付き移動取り消し。秒数の微調整は履歴に追加しない
- フロア・卓の追加・名前変更・削除（長押しで削除/フロア名変更）
- 終了通知、複数の終了前通知、振動の端末別設定、OSの通知/アラーム許可画面
- 午前6時の営業日切替、期限切れメンバーの履歴を保存して一覧から削除

## 共有と更新

Firestore REST APIで既存の `shared/watch.state`（version 2）と `shared/main.state.members` を読みます。共有の変更は最新状態を読み、updateTimeを条件に保存します。衝突時は最大3回再試行します。前景で3秒間隔のポーリングです。接続失敗中は直近のキャッシュを表示し、保存に失敗した操作はその旨を表示します。メンバー・卓・タイマーは共通、表示・通知設定は端末内です。

HTMLの変更はこのネイティブ画面に自動反映されません。画面や機能の変更はAPKの再ビルド・更新が必要です。Firebaseのメンバー・卓・タイマーの変更は共有されます。複数端末を厳密な同時刻に表示するリアルタイムリスナーではありません。

## ビルド

JDK17、Android SDK36で `gradlew.bat assembleDebug`。出力 `app/build/outputs/apk/debug/app-debug.apk`。配布用コピーは `DareWatch-debug.apk`。旧版と同じ署名で `adb install -r` を使います。

このPCの既存ビルド環境は `%LOCALAPPDATA%/Temp/DareWatchBuild/` にあります。Gradle実行時にJAVA_HOMEとANDROID_HOMEを指定します。

## 実機確認

2026-10-30、接続中のGalaxy Watch4（396×396）に上書きインストールし、起動・Firebase読込・一覧・操作画面・時間ポップアップを確認。AndroidRuntimeのクラッシュなし。

`src/debug/java/jp/dare/watch/NativeChecks.java` はAndroidの実行環境で、Firestore型変換、時間候補の停止状態、再生/一時停止、微調整、卓別時間復元、移動と取り消し、日替わりアーカイブを独立したダミーデータで検証します。Firebaseへの書込は行いません。

通知の振動・消灯中の配信時刻は、実際の通知許可、おやすみモード、省電力設定、正確なアラームの許可に依存します。実業務での時間経過確認は別途必要です。

## 2.1 日別実績入力

操作画面の「取り消し」を「入力」に変更。営業日（朝6時切替）とメンバー名を表示し、本指名数・フリーバック数・管理アプリの追加実績項目を±1で編集します。保存時に shared/main.state.members の対象 dailyMetrics 日付へ反映します。最新値に今回の増減を加える条件付き保存で、他の日付・項目を維持します。キャンセルは破棄、失敗時は閉じずに再試行できます。
ブラウザ側watch画面にも同じ入力を追加。こちらを公開URLへ反映するにはVercelへの公開が必要です。Wear OS版はAPKの更新で反映します。

## 2.2 実機プレビューと通知の確認

`実機プレビュー.cmd` とPC内の `/preview/server.py` で、接続中の時計の実画面を表示・操作できます。管理画面のウォッチデバッグは「実機」「HTML版」を明確に分け、初期表示を実機にしました。

通知調査では、実機の通知許可・正確なアラーム許可・チャンネルは有効で、終了時刻のアラーム配信履歴も確認できました。一方、端末のアプリ内振動設定はOFFでした。2.2では前景のお知らせを黄色いバナーで10秒表示し、設定に5秒後の通知テストを追加しました。振動OFFの設定は自動変更しません。振動を希望する端末では設定からONにしてください。

2026-10-30 実機確認追記：Watch4に2.2を上書きインストール。通知テストの5秒後配信をアプリ前景とホーム画面の両方で確認。前景ではOS通知と黄色いアプリ内バナーを画像で確認。後景ではDareTimersのDelivered（foreground=false）ログとOSのNotificationRecordを確認。直近のテスト設定はvibration=true。PCの実機プレビューも実画面PNGの取得を確認済み。

入力実績の値を使った確認は独立ダミーデータのみ。検証中の誤タップによる卓移動1回は条件付き保存で元に戻し、履歴に取り消し理由を記録しました。タイマーはその操作で5:00へリセットされており、残り時間の精密な復元は行っていません。

## 2.3 一覧の表示領域

検索アイコンをメンバー追加の＋へ変更し、下部固定の＋を廃止。一覧は円形画面の下端まで描画します。末尾はスクロールで上へ移動して、操作ボタン全体を表示できます。ホームの検索絞り込みは廃止し、メンバー追加ポップアップ内の名前検索は維持しています。

## 2.7 全画面モーダルと端スワイプ

小さなポップアップ枠を廃止し、全画面のモーダル層に変更。メンバー追加一覧は文字と行を拡大し下端までスクロールできます。左端から右にスワイプすると前の画面へ戻ります。モーダルの履歴を管理するため、推移卓設定から戻るとメンバー追加へ復帰します。実機ではOS側の端スワイプと競合しないよう調整し、戻るジェスチャーの認識と一覧画面への復帰を確認しました。

## 2.8 戻るスワイプの描画

キャスト操作画面も指に合わせて右へ移動し、下にあるメンバー一覧が見えるように変更。指を離すと画面外までスライドし、短い操作なら元の位置へ戻ります。×や端末の戻る操作でも同じアニメーションを使います。実機でスワイプ途中の表示と復帰を確認しました。

## 2.9 卓移動ボタン

操作画面の下端の空白全体を青い「次の卓へ」ボタンに変更。以前の位置には確認付き「戻す」を復活し、入力と並べました。新しく行う卓移動では移動前のタイマー状態も保存し、戻すと復元します。旧履歴でタイマーの記録がない場合は元の卓の設定時間を停止状態で復元します。ダミーデータで復元を検証済み。

## 2.10〜2.12 一覧と操作の視認性

リセットと再生のアイコンを大きい図形で描画し、一覧タイマーの数字を拡大。卓移動は一覧・操作画面の両方で確認画面を表示し、移動元・移動先が他端末で変わった場合には再確認を求めます。

上部の大きさ・表示順・設定は横幅全体を3分割する仕切り型ボタンに変更。メンバー追加、キャスト行も横幅全体を使います。キャスト行の右側は上下に分け、上が再生/一時停止、下が次の卓です。卓移動の確認画面はキャンセルまで実機で検証しました。

## 2.15 通知の移動案内

終了・終了前通知に、キャスト名とフロア付きの移動元・移動先を保存し、OS通知は名前を見出しに「移動元 ↓ 移動先」の大きい本文スタイルに変更。アプリ前景のお知らせも名前と移動元・移動先を3段で大きく表示します。通知テストは現在の共有データの先頭キャストを使い、卓移動自体は行いません。実機テストで配信と大きい案内表示を確認しました。既に届いている旧通知は古い表示のままです。

## 2.18 アプリ使用中の通知画面

黄色いアプリ内バナーを廃止。前景で通知時刻になると、黒背景で名前・移動元・下向き矢印・移動先を大きく表示する全画面の通知を自動表示します。「閉じる」または左端からのスワイプで操作中の画面へ戻ります。表示中の同一キャストへの新しい通知は更新し、別キャストの通知は順に確認できます。

アプリ表示中はOS通知を低優先度の履歴チャンネルへ保存して二重ポップアップを防ぎ、振動設定は適用します。アプリを閉じている間は従来の高優先度OS通知で知らせます。実機の通知テストで前景の全画面表示と戻る動作を確認しました。


## 2.19 スワイプ戻りとスマホ操作画面

ウォッチ画面の×・キャンセル操作をなくし、左端から右への戻るスワイプで閉じるようにしました。移動確認・実績保存・推移保存の主操作は画面幅を使って大きく表示します。スマホ用に /watch/phone.html を追加し、キャスト一覧画面の「付け回し」から通常の操作画面として開けます。スマホ表示は円形枠を外して縦長画面に最適化し、時計と同じFirebaseのメンバー・卓・タイマーを使います。
