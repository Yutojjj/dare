# HTML遠隔更新の検証状況

## Web側の起動短縮（2026-10-31）

Firebase SDKを画面表示を妨げない読み込みへ変更し、共有から正常取得できた一覧を `watch-confirmed-state-v1` に保存。次回起動ではその一覧を先行表示し、共有の最新状態を確認してから編集を許可する。同期前のキャッシュは共有へ送信せず、通知予約にも使用しない。通信失敗時は表示専用を維持し、再接続・再表示時に確認を再試行する。初回と保存データがない場合は共有取得まで待つ。APKの変更なし。

隔離ブラウザで、SDK取得遅延中の先行表示、編集ロック、通信失敗からの再接続、最新データへの置換、未確認キャッシュの未送信を確認。既存の小型画面チェックと17件のタイマー・実績・スワイプテストも成功。Geckoエンジン自体のコールド起動時間はこのWeb側変更の対象外。

## 2.26 通知の修正（2026-10-31）

WebWatchActivityをNativeTimersの前面通知へ接続し、ブラウザの描画やFirestore通信に依存しない黒い通知画面を追加。名前・通知時点・現在卓→次卓を縦に表示し、右スワイプで元の画面へ戻る。同時通知は順に表示。前面の明示的な振動も既存NativeTimers経由で実行する。

タイル閲覧時に受信した共有タイマーもNativeTimersへ同期・再予約する。終了前通知などの端末設定は共有データと別に保持し、タイルの更新で消えないようにした。APK更新後にも既存の通知予約を復元する。

共有データへ接続しない5秒の専用ページで、SM-R860上の前面通知（ゆう／2階・8卓↓2階・7卓）の表示を確認。ログで `vibration=true foreground=true` の配信も確認。振動の強さ・体感は利用者側の確認が必要。

同じ隔離ページからアプリを閉じて5秒テストも実施。`foreground=false` の配信とOSへの通知登録は成功したが、SysUIが `Not alerting: Device is off-body` と記録しており、非装着判定のため通知表示・振動が抑制された。装着状態での体感確認は未実施。通知設定を勝手に変更する回避策は入れていない。

## 2.24（2026-10-31）

一覧タイル `WatchTileService` をWeb検証版に追加。3名まで卓・タイマーを表示し、タップは `castId` を安全なネイティブメッセージでページへ渡して操作画面を開く。タイル閲覧時に共有データを読み直し、アプリから受信した状態もキャッシュする。対応するタイル描画エンジンでは秒単位の残り時間を端末内で計算し、非対応時は終了予定時刻を表示する。操作はアプリで実施。タイル自身は共有データを変更しない。日付切替・タイマー並び・停止時間の3件の単体テスト成功。インストール後「タイルを追加」から「付け回し一覧」を追加する。

2.23から、一定時間の復帰後の強制再読み込みを除去。画面完成を待つ起動カバーに変更し、Firebase初回取得と購読の重複を除去。戻るスワイプ確定時に22msの短い振動を実行。内側では画面を戻し、ルート一覧ではActivityのタスクを終了する。ルートで終了した後の表示先はOSのタスク状態に従う。

目的：Vercelの `/watch/` をAPK同梱のGeckoViewで表示し、画面はWeb公開で更新する。AlarmManager・通知・振動は既存のNativeTimersに残す。

`assembleWebPreview` は標準版と別の `jp.dare.watch.webpreview` を作る。通常の `assembleDebug` は既存のネイティブ版。検証版のActivityは `WebWatchActivity`。ウォッチ4のarmeabi-v7aでビルド成功。検証版は約156MB。
